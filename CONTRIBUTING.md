# Contributing to Domoticz-Zigbee

Thank you for your interest in contributing to **Domoticz-Zigbee**! We appreciate your time, ideas, and effort — whether you’re fixing a bug, adding a feature, improving documentation, or helping others in discussions. 😊

This document outlines guidelines to make it easy and clear to contribute in a way that keeps the project healthy and maintainable for everyone.

---

## 💡 What You Can Contribute

You can help out in several ways:

* 🐛 **Bug reports & troubleshooting tips**
* 🔧 **Code improvements & new features**
* 🧪 **Tests for bugs and features**
* 📚 **Documentation improvements**
* 🌍 **Translations for the Web UI and docs**
* 🗣️ **Support and guidance in discussions**

Our wiki has installation and usage info — check here before submitting issues or PRs: [https://zigbeefordomoticz.github.io/wiki](https://zigbeefordomoticz.github.io/wiki)

---

## 🌱 Getting Started

1. **Fork the repository** on GitHub.
2. **Clone your fork locally**:

   ```sh
   git clone https://github.com/<YOUR-USERNAME>/Domoticz-Zigbee.git
   ```
3. **Create a new branch** for your work:

   ```sh
   git checkout -b feature/my-feature
   ```
4. Make your changes and **test thoroughly**.
5. **Commit your work** with a clear message.
6. **Push the branch** to your fork.
7. Open a **Pull Request** back to this repo’s main branch.

---

## 📝 Issue Guidelines

When opening an issue:

* Use a **descriptive title**.
* Include **steps to reproduce**, expected vs. actual behavior.
* Add logs or screenshots if relevant.
* Search existing issues before opening new ones.

Issues are not just for bugs — feel free to open one for enhancement ideas too.

---

## 🙌 Pull Request Checklist

Before submitting:

✅ Your changes are on a **feature branch**, not `main` or `stable`.
✅ Your PR has a **clear title and description** explaining the change.
✅ You linked related issues (if any).
✅ All new and existing tests pass.
✅ You followed the project’s **coding style**.
✅ Documentation was updated if the change affects user behavior.

---

## 🧠 Coding Style

We strive for consistency and clarity:

* Follow the existing style and patterns in the codebase.
* Format Python code according to the current rules (PEP-8 compatible linters if configured).
* Add comments for non-obvious logic.

---

## 🤝 Review Process

* PRs will be reviewed by maintainers.
* A reviewer might suggest changes — feel free to ask questions or respond.
* You can work with maintainers until your PR is ready to merge.

We aim to be welcoming, friendly, and supportive — and expect contributions to follow that spirit too.

---

## 📜 Code of Conduct

By participating, you agree to abide by the project’s Code of Conduct (see `CODE_OF_CONDUCT.md` if available). Be respectful, patient, and inclusive toward others.

---

## ❓ Questions & Support

For general discussions, questions, or announcements, check out the **Discussions** tab on GitHub.

---

Thank you for helping make **Domoticz-Zigbee** better! 🚀
